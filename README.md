## OpenCode в GitHub Actions

Воркфлоу `.github/workflows/opencode.yml` запускает OpenCode по новым комментариям (`created`) к issue, pull request и строкам diff. Команды вызова — `/opencode` и `/oc`; запуск доступен только авторам с ролью `OWNER`, `MEMBER` или `COLLABORATOR`, комментарии ботов игнорируются.

Используется модель `kimi-code-plan-global/k3-256k` подписки Kimi For Coding. Для работы необходимо установить [OpenCode App](https://github.com/apps/opencode-agent) на репозиторий и сохранить ключ международного региона `kimi.ai` в Actions Secrets под именем `KIMI_API_KEY`. Агент авторизуется через GitHub App и OIDC; публикация сессий отключена (`share: false`). Для команд `gh` внутри агента используется автоматически выдаваемый GitHub `GITHUB_TOKEN` с правом `issues: write`, передаваемый через переменную `GH_TOKEN`; отдельный секрет для него не нужен.

Время выполнения ограничено 15 минутами. Запуски в рамках одного issue или pull request выполняются последовательно: новая команда отменяет предыдущий запуск. Ответ агента появляется в обсуждении issue или pull request, а журнал — на вкладке [Actions](https://github.com/rustamomarov743-art/ai-for-developers-project-387/actions).

### Автотриаж issues

Воркфлоу `.github/workflows/opencode-triage.yml` автоматически разбирает новые обращения по событию `issues: [opened]`. Он запускается только для авторов с ролью `OWNER`, `MEMBER` или `COLLABORATOR`, игнорирует ботов и пропускает issues с меткой `ready-for-agent`: спецификации и тикеты, подготовленные скиллами, повторного триажа не требуют.

Агент проверяет обращение с учётом существующего кода, публикует предварительный разбор и вопросы, применяет category- и state-метки. Он не меняет код, не создаёт ветки, PR, спецификации или тикеты и не начинает реализацию без явной команды человека. Для комментариев и меток используется `GH_TOKEN` с правом `issues: write`; чтение репозитория и ответ OpenCode остаются на стандартной авторизации через GitHub App/OIDC.

Время выполнения ограничено 15 минутами. Запуски одного issue выполняются последовательно: новый запуск отменяет предыдущий через `concurrency`.

Для остановки текущего запуска используйте **Cancel workflow** на странице прогона. **Disable workflow** в меню воркфлоу запрещает новые запуски; после проверки или обслуживания включите воркфлоу обратно через **Enable workflow**.

## Сценарий

1. Путь владельца
- создаёт тип встречи;
- указывает название, описание и длительность;
- просматривает общий список предстоящих встреч.

2. Путь гостя
- открывает публичную страницу владельца
- выбирает тип встречи;
- открывает календарь на ближайшие 14 календарных дней;
- выбирает свободный слот;
- указывает имя и email;
- записывается и получает подтверждение.

3. Результат бронирования
- встреча появляется в списке владельца;
- занятое время больше недоступно;
- запрещены любые пересечения интервалов, даже между разными типами встреч;
- следующая встреча может начинаться ровно в момент окончания предыдущей;
- правило должно соблюдаться и при одновременных запросах.

4. Ограничения
- владелец только один и задан заранее;
- регистрации и авторизации нет;
- внешних календарей и уведомлений нет.
